# Maven Detective

Explains why a Maven build fails: a diagnosis card with cause, evidence, confidence (`certain`/`likely`) and a quick fix. Language in the project: code comments, commit messages and the base texts of the error catalog are **German**; every Markdown file published on GitHub (README, CHANGELOG, CONTRIBUTING, `docs/` …) is **English**. Package prefix `io.github.bitshiftdev.mavendetective`.

## Modules

| Module | Purpose | Java |
| --- | --- | --- |
| `core` | Model, log parser, event format, YAML subset, rule engine, checks, fix execution, CLI, snapshots (`snapshot/`), IDE vs. CLI (`env/`), module A (`deps/`) | **Java 8 bytecode** (`release 8`), tests Java 17 |
| `maven-extension` | `DetectiveEventSpy`: events as JSONL + card in the Maven log; embeds `core` into the JAR | Java 8 |
| `intellij-plugin` | Tool window "Maven Detective", `MavenRunListener`, quick fixes (`FixRunner`), inspections | Toolchain 21, against IntelliJ 2025.3 (`sinceBuild 253`); needs the Maven and Java plugins |
| `fixtures/` | One project per error category that triggers the failure on purpose | – |

Concept/roadmap: `Maven Detective – Plugin-Konzept.md` (module A dependency analysis, module B Build Doctor, gates; local only). Features and usage: `README.md`.

## Hard rules

- **`core` has no runtime dependencies.** It runs in Maven's class loader; JSON (`io/Json`) and YAML (`io/MiniYaml`) are hand-written. Do not add a library.
- **Java 8 API in `core` and `maven-extension`**: no `var`, no records, no `List.of`, no `String.isBlank`, no text blocks, diamond only where Java 8 allows it (the code uses explicit type arguments `new ArrayList<String>()` – keep that style). The CI job `extension-on-java8` runs the fixtures on Java 8.
- **Checks only read** files/settings, change nothing and never use the network.
- **The extension never changes the build** and swallows every internal error.
- **Access the IntelliJ Maven API only through `IdeMaven`** (adapter layer).
- The IDE does **not** attach the extension: IntelliJ sets `-Dmaven.ext.class.path` itself for its listener; a second value would override it. The IDE uses the text log + its own Maven model.
- **No user-facing text in core code:** `Texts.t("key", args…)` (`core/Texts`, files `core/…/texts.properties` = English/default, `texts_de.properties`; a new key always goes into both). Hand-made placeholders: `{0}` unchanged (no thousands separators), `{0|one|more}` by number (the words may contain `{0}`); named `{artifact|…}` stay as they are for the catalog templates. Language: `Texts.setSource` (plugin) > `-DmavenDetective.language` (CLI also `--lang`) > `MAVEN_DETECTIVE_LANGUAGE` > JVM locale (`de` → German, otherwise English). Core tests run with `de` (Gradle `systemProperty`), `run-fixtures.sh` exports `de`. Enum texts via prefix + `name()` (`confidence.*`, `change.area.*`, `usage.kind.*`). Only catalog validation, the YAML/JSON parsers and the POM tag scanner stay German. `TextsTest` checks keys/placeholders of both files and `_en` in the catalog.

## Diagnosis flow

Collect error lines (events JSONL or text log via `MavenLogParser`) → every rule tests its `patterns` (named groups → variables) → the checks from `checks` run in order → the first **confirming** check with its own cause replaces `cause` and supplies the first quick fix, otherwise the rule text applies. If several rules match, the higher `priority` wins.

## New rule (error catalog)

File: `core/src/main/resources/io/github/bitshiftdev/mavendetective/core/catalog/build-doctor-v1.yaml`. The fields are documented in the file header (`id`, `number`, `category`, `priority`, `confidence`, `patterns`, `extract`, `unless`, `checks`, `cause`, `fix`).

1. Add the rule. Regexes **always in 'single quotes'** (apostrophe as `''`). MiniYaml supports no anchors, tags, flow mappings or multiple documents.
2. Placeholders in `cause`: `{var}`, `{var|fallback text}`, `{a,b|fallback}`. **Directly below every `category`/`cause`/`label` (also in pattern mappings and `fix`) add `…_en:`** – the base text is German, `TextsTest.katalogHatJedenTextAufEnglisch` checks it (`_de` would work too, `Rule.getX()` picks via `Texts.pick`).
3. **Mandatory:** ≥3 test logs `core/src/test/resources/logs/<rule-id>__<description>.log` (variants: Maven 3.9 / Maven 4 or a second message form / CI prefix or Windows). `LogCatalogTest` checks that every file is recognised as the rule in its name and that every rule has `MIN_LOGS_PER_RULE` = 3 logs. Windows logs with CRLF: put `crlf` in the file name (`.gitattributes` exempts it from LF normalisation).
   - Near misses: `logs-negative/<rule-id>__<description>.log` – the rule must appear in **no** diagnosis (warnings instead of errors, 403/ZipException/ClassNotFoundException from tests).
   - Two errors: `logs-multi/<higher-rule>+<lower-rule>__<description>.log` – the higher `priority` comes first, the other follows (file name must be ordered by priority).
4. If reproducible: fixture under `fixtures/NN-name/` + a line in `fixtures/fixtures.txt` (`<dir> | <rule-id> | <mvn-args>`; optional `setup.sh`, which gets the local repository as `$1`). `run-fixtures.sh` checks the events path **and** the log fallback **and** that the card appears in the log.
5. Update the README table/sections if categories or checks are added.

## New check

- Interface `core/check/Check` (`id()`, `run(CheckContext)`); result `CheckResult.notApplicable()` / `info()` / `confirmed()`, chainable with `.cause(template)`, `.evidence(Evidence…)`, `.fix(FixAction)`, `.var(name, value)`.
- `CheckContext`: `failure()`, `env()`, `var()`, `lines()`, `projectPoms()`, `find(Pattern)`, `anyLineContains()`.
- Put it by topic into `ResolutionChecks`, `RepositoryChecks`, `PomChecks` or `RuntimeChecks` as a `static final class` and register it in their `all()` or in `Checks.defaults()` (duplicate IDs throw).
- Test in the class of its topic (`PomChecksTest`, `ResolutionChecksTest`, `RepositoryChecksTest`, `RuntimeChecksTest`), calling `run` directly via `testkit/CheckBench` (home, local repository and project in a `@TempDir`; `.line(…)`, `.var(…)`, `.failedRequest(…)`, `.pomProblem(…)`, `.mojoError(…)`, `.offline()`, `.runner(…)`) and `testkit/Diagnoses` (`assertConfirmed/Info/NotApplicable`, `assertFirstFix(list, type, key, value…)`, `assertEvidence(list, file, line)`). One test each for confirmed / info / not applicable, as far as the check can produce that status; compare variables, fix type + parameters and file + line, not texts. End-to-end through the catalog: `ChecksTest`. Extend the README list "Available checks".
- `ChecksContractTest` runs **every** registered check automatically: no file in project/home/repository changes, no network (`ProxySelector` that throws), garbage variables (`:`, `a:`, `99999999999`, UNC, `\0` …) throw nothing. A check that reads a new variable ⇒ add its name to `VARS` there.
- Numbers from log text: bound the regex (`\d{1,9}` for `int`) or use `Text.number(s)` / `Text.javaForClassVersion(String)` (−1 if not a number or too large) – never a bare `Integer.parseInt` on a log group. Splitting `g:a` ⇒ `split(":", -1)` + check length and empty parts.
- `BuildDoctor` checks `Cancellation` per rule and passes it to `ProjectPoms`; a check that loops over many files/JARs calls `ctx.cancellation().check()` outside any `catch`.

## Quick-fix types

Constants in `core/diagnosis/FixAction` (the Javadoc table lists the parameters): `rebuild`, `delete-files`, `open-file`, `replace-in-file`, `switch-jdk`, `set-jvm-option`, `insert-plugin-version`, `show-dependency`, `pin-version` (module A; `file`, `artifact`, `version`), `remove-exclusion` (A4; `file`, `artifact`, `exclusion`, `section`), `add-exclusion` (A3; `file`, `artifact` = direct dependency under `dependencies`, `exclusion`), `add-dependency` (A5; `file`, `artifact`, `version`/`scope`/`type`/`classifier` only when needed), `remove-dependency` (A5; `file`, `artifact`, `classifier`), `set-scope` (A5; `file`, `artifact`, `scope`, `classifier`), `set-version` (A6; `file`, `version` + `property` (missing → create) or `artifact` + `section` = `parent`/`dependencies`/`dependencyManagement`), `manual`. POM types go centrally through `PomEditor.forFix`/`isPomFix` (core: `FixExecutor`, plugin: `FixRunner.editPoms` = one undo step + reimport). `core/fix/FixExecutor` only executes file-based ones (`delete-files`, `replace-in-file`, `set-jvm-option` + POM types); the rest runs in the plugin (`FixRunner`). New type ⇒ FixAction constant + Javadoc + catalog header comment + `RuleCatalog.FIX_TYPES` + execution (POM type: `PomEditor.forFix`/`isPomFix` + `FixRunner.isSupported`/`run`).

## Snapshots ("What changed?")

Stored in `~/.maven-detective/snapshots/<project>-<hash>/` (`green-*.json`, `latest-*.json`); relocatable with `-DmavenDetective.home` / `MAVEN_DETECTIVE_HOME`, off with `-DmavenDetective.snapshots=false`. A green run = new reference; short green runs (`validate`, `-pl`) must not thin out the reference. Between IDE and extension snapshots, only compare what both measure the same way. Fixture `09-changed-since-green` tests green → change version → red.

## Class origin (phase 5: Build Doctor asks module A)

- Checks `class-origin` (rule 10, `runtime-class-conflict`) and `class-location` (rule 9, after `ee-namespace`, `source-location`) in `check/ClasspathChecks` (static `JARS` = shared `JarIndex`). `Project.of(ctx)` builds a `PomLocator` from `ctx.projectPoms()` + `env.getLocalRepository()`; module = source file (nearest project `pom.xml`) > `ErrorRecord.getProject()` (log: artifactId, events: g:a:v) / `on project X` > the only non-`pom` module, otherwise `notApplicable`.
- `deps/ClassOrigin.find(locator, module, reactor, tree|null, projectFiles, Target, index, cancel)`: no tree → `DependencyResolver`; locations `Where` CLASSPATH (classpath order, package search without `isSelf`) → DISPLACED (CONFLICT node and `premanagedVersion` ≠ version, JAR of the requested version available locally) → EXCLUDED (`ExclusionAudit.audit` per project POM of the chain, only USED and declared in the model; only if the class is not on the classpath, or for packages); `searchRepository` (longest repository directory for the package, ≥ 2 levels, > 600 JARs → give up, highest version per g:a). `Target.type/pkg/member`; JarIndex knows no inner classes (`indexName()`).
- `deps/ClassFile`: mini parser (constant pool, fields, methods) + `Member` from messages: JDK 11+ `'Ret owner.name(Type, …)'` → descriptor, JDK 8 `owner.name(desc)ret`, fields only JDK 17+ (`does not have member field 'type NAME'`). `Hit.getHasMember()` = this copy knows a member with exactly this descriptor.
- Evaluation: ≥ 2 on the classpath → `DuplicateClasses.analyze` + `Clash.fixesFor(loaded)` if it lacks the member, otherwise a recommendation; 1 → displaced version with the member ⇒ `Project.raise` = `UpgradeSimulator.simulate` over the project POMs of the chain, only with exactly one step, without `note` and if `targetAfter` matches; 0 → exclusion (`remove-exclusion`) > displaced (higher → raise, lower → note "no longer exists") > local repository (`add-dependency`, cause as INFO so that the fix comes first). Compiler: hit with scope test/runtime → `set-scope compile` (inherited → `open-file`, transitive → `add-dependency`); visible hit → note only (reactor module → rebuild with `-am`). `Could not initialize class` → its own cause (static initializer), not a classpath problem.
- Tests: `check/ClasspathChecksTest` compiles real classes with `javax.tools` (`--release 8`) into JARs of a `@TempDir` repository; `ClasspathChecksTestAccess.compile` for other packages (`deps/ClassFileTest`). No fixture (Surefire would need the network).

## Preflight (`core/preflight/`) and log navigator (`core/io/LogOutline`)

- `Preflight.run(projectDir, BuildSetup, Options)` → `Report` (`Item` per finding: `Topic` SETTINGS/JDK/MAVEN/PROJECT/LOCAL_REPOSITORY/REPOSITORY, `Status` OK/INFO/WARNING/ERROR, `Evidence`, `FixAction`s as on the card; `getLight()` GREEN/YELLOW/RED, `getLocalRepository()`). Every check yields ≥1 row. `PreflightContext` reads settings.xml (user from `setup.getUserSettings()`, otherwise `~/.m2`; global from `BuildSetup.getMavenHome()/conf`; SAX line from the cause), POMs via `ProjectPoms` + `PomLocator` (`missingPoms()` builds all models first).
- `PreflightChecks`: release = max over modules from `maven.compiler.release/target/source` (interpolated, location = property with the literal value) and `<release>`; with `maven-toolchains-plugin` only INFO + toolchains.xml check; enforcer ranges via `VersionRange` (like the enforcer, unreadable = satisfied). Report a dependency without a version only if the chain and the BOM imports are complete. Never report `maven-default-http-blocker` as an http mirror of its own.
- **Network only with `Options.network(true)`** (`RemoteRepositories` + `RepositoryProbe.HTTP`: HEAD, proxy from settings.xml incl. `nonProxyHosts`, **never credentials**). Tests inject `Options.probe(...)`. Report a missing parent/BOM as "in no repository" only if all repositories answered (401/error → no verdict).
- `BuildSetup.getMavenHome()`: command line = MAVEN_HOME/PATH or the unpacked wrapper distribution (`~/.m2/wrapper/dists/…`); the IDE sets `IdeMaven.mavenHome`. `MavenSettings.getProxies()/activeProxy(protocol)`.
- `LogOutline.of(lines)`: lines 0-based; modules (`---< g:a >---` + `Building …`), plugin steps (`--- mojo (exec) @ x ---`), reactor summary (result/time), `BUILD SUCCESS/FAILURE`, `getFirstError()` skips `NOT_A_CAUSE` (`COMPILATION ERROR :`, `Tests run:` …), download runs ≥ `MIN_FOLD` as a `Fold`. `isDownloadNoise(line)` is also the basis of the console folding (fast exit, tolerates ANSI/`\r`/`\n`).
- Plugin: `BuildDoctorPanel` has the views card/setup/preflight/log (`showView`). `PreflightView` (host: back/check/runFix) – fixes run through `FixRunner.run` with a synthetic `Result` (session repository = preflight repository, parameter `args` removed → no rebuild). `BuildDoctorService.preflight(network, cancel)` (IDE setup, not on the EDT) + `preflightDone` → `Listener.preflightChanged` (tile in `OverviewPanel`). `LogNavigatorView` (Disposable, editor via `EditorFactory.createViewer`, `clean()` removes ANSI/`\r` – documents only know `\n`). `DownloadConsoleFolding` (`console.folding`, setting `foldDownloads`). Actions `MavenDetective.Preflight` (also in `Maven.NavigatorActionsToolbar`) and `MavenDetective.ShowLog`.
- Bundle: do not nest `{n,number,#}` inside `choice` (pass a second string parameter); never assemble keys (`MavenDetectiveBundleTest` looks for literals) – `switch` on the enum.

Extension properties: `-Dmaven.ext.class.path=<jar>`, `-DmavenDetective.eventsFile=…`, `-DmavenDetective.report=false`.

## Module A (`core/deps/`, tab "Dependencies")

- `PomFile`: raw POM via SAX **with line numbers** (properties, dependencies, dependencyManagement, parent); profiles are not evaluated, only reported.
- `PomLocator`: parent via `relativePath` → reactor → local repository; never the network; missing POMs in `getMissing()`.
- `EffectiveModel`: rebuilds Maven's order – inherit (child wins), interpolate in the context of the **child**, then BOM imports (first wins, the BOM is interpolated in its **own** context). Every value keeps file+line.
- `VersionExplainer` → `VersionExplanation` (steps with `Kind`, file, line, level; `Source` DIRECT/MANAGED/BOM/TRANSITIVE/UNKNOWN). Tree optional (`DepNode`, from the IDE's `IdeMaven.dependencyTree` or `DependencyTreeParser` for `dependency:tree -Dverbose`).
- Tests build a project + local repository in a `@TempDir` (`VersionExplainerTest`). Plugin: `DependenciesPanel`, `WhyThisVersionAction` (EditorPopupMenu, `pom.xml` only).
- **A2** `ConflictMatrix.build(locator, root, poms, trees)`: cell per module from the tree (INCLUDED, BFS), without a tree only direct dependencies (`isPartial`). Divergent row → `Pin` in the **nearest common parent within the project**, version = `MavenVersion.max`; `Blocker` = a direct `<version>` or management closer to the module (BOM imports never block). Columns without cells for `packaging pom` are dropped.
- `PomEditor.pinManagedVersion` → `Edit` (offset/length/text/line): own tag scanner, only paths directly under `project` (profiles untouched), keeps indentation/line endings; existing entry → change the version or the `${prop}` of the same POM. No DOM round trip. The plugin applies the `Edit` to the `Document` (undo), `FixExecutor` to the file.
- Plugin: tab `ConflictMatrixPanel` ("Conflicts"), double-click → `DependenciesPanel.show`; after a pin `IdeMaven.reimport`. CLI: `matrix [--tree …] [--all] [--markdown] [--pin g:a[:version]]`.
- **A4** `ExclusionAudit.build/audit`: for each `<exclusion>` (only those written in the POM, `dependencies` + `dependencyManagement`) rebuild the transitive tree of the dependency from local POMs (`Closure`: compile/runtime, without optional, deeper exclusions apply, first hit per GA wins, management of the **checking** module before the value in the dependency's POM) – once without exclusions, once with the remaining ones. Status `USED`/`REDUNDANT`/`STALE`/`UNKNOWN`; a missing POM → `UNKNOWN`, never `STALE`. `PomFile.Dep` has `getExclusionEntries()` (with line, `matches` with `*`) and `isOptional()`.
- `PomEditor.removeExclusion(xml, g, a, "eg:ea", managed)`: the scan now knows all dependencies (`DepEntry` incl. exclusions); the last exclusion takes `<exclusions>` with it, whole lines are removed; with duplicates the first one.
- Plugin: `StaleExclusionInspection` (localInspection XML, `<depends>com.intellij.modules.xml</depends>`, description `inspectionDescriptions/MavenDetectiveStaleExclusion.html`) reads the saved file, maps findings to the PSI by structure (not lines), the quick fix deletes the PSI tag. Static `PomCache` (mtime+size) via `PomLocator(root, repo, cache)`.

- **A3** `ModuleClasspath.of(locator, pom, tree, reactor)`: with a tree, INCLUDED nodes in pre-order (= Maven 3 classpath), `directDependenciesBringing(ga)` also counts CONFLICT/DUPLICATE paths; without a tree, `ExclusionAudit.Closure` per direct dependency (now has `decls`), nearest wins, tie → first declaration, order estimated. Managed scope/exclusions are merged in. `target/classes` of the module (`isSelf`) and of reactor modules. JAR path by repository layout (`test-jar`→`-tests`, `ejb-client`→`-client`, timestamped snapshots → `-SNAPSHOT` folder).
- `JarIndex` (thread-safe, cache by mtime+size; the plugin keeps a static instance): class name + CRC32 from the central directory; without inner classes, `module-info`, `package-info`, `META-INF/`.
- `DuplicateClasses.build(locator, poms, trees, index, cancellation)` → `ModuleResult` (clashes, `unreadable`) → `Clash` per JAR group (`differing`, `isMain` = ≥2 non-test JARs). Recommendation: table `KNOWN` (drop/keep GAs) before "fully contained" (with several: transitive before direct, otherwise today's loser); otherwise `drop == null`. `fixesFor(entry)`: `add-exclusion` per direct dependency (in the POM where it is declared), declared directly → `open-file`.
- `PomEditor.addExclusion(xml, g, a, "eg:ea")`: only `project/dependencies`, prefers entries without a classifier, duplicate → `IllegalArgumentException`. Plugin: tab `DuplicateClassesPanel` (checks only on click), `FixRunner.addExclusions` = one undo step + reimport.
- **A5** Basis = classes the sources **name** (`ClassUsages`: main/test, first location, wildcards with the simple names of the file). CLI: `SourceScanner` (text without comments/strings, `src/{main,test}/{java,kotlin,groovy}` + `target/generated(-test)-sources`). IDE: `IdeUsages.collect` (a PSI visitor resolves references, per file `ReadAction.nonBlocking().inSmartMode().executeSynchronously()` + `ClassUsages.addAll`, Kotlin/Groovy via the scanner); the plugin depends on `com.intellij.java`.
- `DependencyUsage.build(locator, poms, trees, index, UsageSource, cancel)`: name → entry (strip inner classes/members; main: first compile/provided/system, otherwise runtime; test: first). `UNDECLARED` (not direct, not declared; `isViaBundle` = via a starter without classes → CLI only with `--all`, IDE via option), `UNUSED` (no name; a starter counts as used if something it brings is named; runtime + table `RUNTIME_ONLY` never; `JarIndex.Contents.getServices()` ⇒ `isCertain=false`), `TEST_ONLY` (compile/provided, only tests). Inherited declaration → only `open-file`. Reactor modules without `target/classes` from source file names. Without sources no UNUSED.
- **A6** `DependencyResolver.resolve(locator, pom)` → `Tree` (DepNode tree like `dependency:tree -Dverbose`, `getMissing()`): BFS, nearest wins/first declaration, the module's management for version/scope/exclusions of transitive dependencies (`premanaged*` set), test/provided/system/optional not transitive, scope like `JavaScopeDeriver`, the winner takes the widest scope (`JavaScopeSelector`). Losers CONFLICT/DUPLICATE/CYCLE, not expanded.
- `UpgradeSimulator.simulate(locator, poms, Request, realTrees, cancel)`: `Planner` looks for the lever – parent (`Target.PARENT`) → BOM import in the model (`BOM`) → artifact: direct `<version>` / management in the project / `${p}` (defined in the project → there, outside → override in the topmost project POM) / BOM with the same version number → raise the BOM / otherwise `pin-version` in `topmost` (topmost project POM of the chain); `Request.pinned()` (`--manage`) forces a pin; `Request.property` (`name=value`). Steps = FixActions (`set-version`/`pin-version`, parameter `current`), applied in memory via `PomEditor.forFix` → `PomLocator.withOverrides(Map<Path,String>)` (parses via `PomFile.parse(path, xml)`, own cache). Both trees with `DependencyResolver` (never mix the real tree with the simulation). `ModuleResult`: `Delta` (ADDED/REMOVED/UPGRADED/DOWNGRADED/SCOPE over INCLUDED nodes per g:a:type:classifier), new `Risk` (a CONFLICT loser requests a higher version), `note` (target stays old, text from `VersionExplainer`), `deviation` (simulated-before vs. real tree). `missing` = only newly missing.
- `PomFetcher`: the only network access in module A, only on request. Temporary POM with the missing GAVs as `type=pom` + the `<repositories>` of the project POMs, `maven-dependency-plugin:3.8.1:collect` (POMs only), `-Dmaven.repo.local`; `executable()` = `./mvnw` > `<mavenHome>/bin/mvn` > `mvn`. Up to 4 rounds, stops when there is no progress. `UpgradeSimulator.localVersions(repo, g, a)` for suggestions.
- `PomEditor.setVersion(xml, section, g, a, v)` (parent/dependencies/dependencyManagement, prefers entries without a classifier) and `setProperty(xml, name, v)` (missing → into `<properties>` or a new `<properties>` before dependencyManagement/dependencies/build). The scan knows `parentFields/parentRanges`, `propertiesRange`, `dmStart`.
- Plugin A6: tab `UpgradeSimulatorPanel` ("Upgrade Simulator"; suggestions from trees/parents/BOM imports, versions from the local repository; "Download Missing POMs" = `Task.Backgroundable` with the IDE's `JAVA_HOME` and `IdeMaven.mavenHome`; "Apply" = `FixRunner.editPoms`), `SimulateUpgradeAction` (EditorPopupMenu, `<dependency>` or `<parent>`).
- `DependencyUsage.undeclared(cp, entry, class, test, file, line, index)` for the live inspection `UndeclaredDependencyInspection` (Java imports; classpath cached on `ProjectRootManager` + POM; `ModuleClasspath.find(Path | g, a)`).
