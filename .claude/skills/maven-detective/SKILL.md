# Maven Detective

Erklärt, warum ein Maven-Build scheitert: Diagnose-Karte mit Ursache, Belegen, Sicherheit (`certain`/`likely`) und Quick-Fix. Sprache im Projekt (Code-Kommentare, Texte, Commits, README): **Deutsch**. Paket-Präfix `io.github.bitshiftdev.mavendetective`.

## Module

| Modul | Zweck | Java |
| --- | --- | --- |
| `core` | Modell, Log-Parser, Event-Format, YAML-Subset, Regel-Engine, Prüfungen, Fix-Ausführung, CLI, Schnappschüsse (`snapshot/`), IDE-vs-CLI (`env/`), Modul A (`deps/`) | **Bytecode Java 8** (`release 8`), Tests Java 17 |
| `maven-extension` | `DetectiveEventSpy`: Events als JSONL + Karte im Maven-Log; bettet `core` ins JAR ein | Java 8 |
| `intellij-plugin` | Tool-Window „Maven Detective“, `MavenRunListener`, Quick-Fixes (`FixRunner`), Inspections | Toolchain 21, gegen IntelliJ 2025.3 (`sinceBuild 253`); braucht Maven- und Java-Plugin |
| `fixtures/` | Ein Projekt je Fehlerkategorie, das den Fehler absichtlich auslöst | – |

Konzept/Roadmap: `Maven Detective – Plugin-Konzept.md` (Modul A Dependency-Analyse, Modul B Build Doctor, Gates). Stand und Nutzung: `README.md`.

## Harte Regeln

- **`core` hat keine Laufzeit-Abhängigkeiten.** Er läuft im Maven-Classloader; JSON (`io/Json`) und YAML (`io/MiniYaml`) sind selbst geschrieben. Keine Bibliothek hinzufügen.
- **Java-8-API in `core` und `maven-extension`**: kein `var`, keine Records, kein `List.of`, kein `String.isBlank`, keine Text-Blocks, Diamond nur wo Java 8 es erlaubt (Code nutzt explizite Typargumente `new ArrayList<String>()` – Stil beibehalten). CI-Job `extension-on-java8` führt die Fixtures unter Java 8 aus.
- **Prüfungen lesen nur** Dateien/Einstellungen, ändern nichts, gehen nie ins Netz.
- **Extension ändert nie den Build** und schluckt jeden internen Fehler.
- **IntelliJ-Maven-API nur über `IdeMaven`** (Adapter-Schicht) ansprechen.
- IDE hängt die Extension **nicht** an: IntelliJ setzt `-Dmaven.ext.class.path` selbst für seinen Listener; ein zweiter Wert würde ihn überschreiben. IDE nutzt Text-Log + eigenes Maven-Modell.
- **Kein sichtbarer Text im Kern-Code:** `Texts.t("key", args…)` (`core/Texts`, Dateien `core/…/texts.properties` = Englisch/Standard, `texts_de.properties`; neuer Schlüssel immer in beide). Platzhalter selbst gebaut: `{0}` unverändert (keine Tausenderpunkte), `{0|eins|mehr}` nach Zahl (Wörter dürfen `{0}` enthalten); benannte `{artifact|…}` bleiben für die Katalog-Vorlagen stehen. Sprache: `Texts.setSource` (Plugin) > `-DmavenDetective.language` (CLI auch `--lang`) > `MAVEN_DETECTIVE_LANGUAGE` > JVM-Locale (`de` → Deutsch, sonst Englisch). Core-Tests laufen mit `de` (Gradle-`systemProperty`), `run-fixtures.sh` exportiert `de`. Enum-Texte über Präfix + `name()` (`confidence.*`, `change.area.*`, `usage.kind.*`). Deutsch bleiben nur Katalog-Validierung, YAML/JSON-Parser, POM-Tag-Scanner. `TextsTest` prüft Schlüssel/Platzhalter beider Dateien und `_en` im Katalog.

## Diagnose-Ablauf

Fehlerzeilen sammeln (Events-JSONL oder Text-Log via `MavenLogParser`) → jede Regel prüft `patterns` (benannte Gruppen → Variablen) → Prüfungen aus `checks` laufen in Reihenfolge → erste **bestätigende** Prüfung mit eigener Ursache ersetzt `cause` und liefert den ersten Quick-Fix, sonst gilt der Regeltext. Bei mehreren passenden Regeln gewinnt die höhere `priority`.

## Neue Regel (Fehlerkatalog)

Datei: `core/src/main/resources/io/github/bitshiftdev/mavendetective/core/catalog/build-doctor-v1.yaml`. Felder sind im Dateikopf dokumentiert (`id`, `number`, `category`, `priority`, `confidence`, `patterns`, `extract`, `unless`, `checks`, `cause`, `fix`).

1. Regel eintragen. Regex **immer in 'einfachen Anführungszeichen'** (Apostroph als `''`). MiniYaml kann keine Anker, Tags, Flow-Mappings, Mehrfach-Dokumente.
2. Platzhalter in `cause`: `{var}`, `{var|Ersatztext}`, `{a,b|Ersatz}`. **Zu jedem `category`/`cause`/`label` (auch in Pattern-Mappings und `fix`) direkt darunter `…_en:`** – Grundtext deutsch, `TextsTest.katalogHatJedenTextAufEnglisch` prüft es (`_de` ginge auch, `Rule.getX()` wählt per `Texts.pick`).
3. **Pflicht:** Testlog `core/src/test/resources/logs/<regel-id>__<beschreibung>.log`. `LogCatalogTest` prüft, dass jede Datei als die Regel im Namen erkannt wird und jede Regel ≥1 Log hat.
4. Wenn reproduzierbar: Fixture unter `fixtures/NN-name/` + Zeile in `fixtures/fixtures.txt` (`<verz> | <regel-id> | <mvn-args>`; optional `setup.sh`, bekommt lokales Repo als `$1`). `run-fixtures.sh` prüft Events-Pfad **und** Log-Fallback **und** dass die Karte im Log steht.
5. README-Tabelle/Abschnitte aktualisieren, falls Kategorien oder Prüfungen dazukommen.

## Neue Prüfung (Check)

- Interface `core/check/Check` (`id()`, `run(CheckContext)`); Ergebnis `CheckResult.notApplicable()` / `info()` / `confirmed()`, verkettbar mit `.cause(template)`, `.evidence(Evidence…)`, `.fix(FixAction)`, `.var(name, value)`.
- `CheckContext`: `failure()`, `env()`, `var()`, `lines()`, `projectPoms()`, `find(Pattern)`, `anyLineContains()`.
- Thematisch in `ResolutionChecks`, `RepositoryChecks`, `PomChecks` oder `RuntimeChecks` als `static final class` ablegen und in deren `all()` bzw. `Checks.defaults()` registrieren (doppelte IDs werfen).
- Test in `core/src/test/.../check/ChecksTest.java`. README-Liste „Vorhandene Prüfungen“ ergänzen.

## Quick-Fix-Typen

Konstanten in `core/diagnosis/FixAction` (Javadoc-Tabelle listet Parameter): `rebuild`, `delete-files`, `open-file`, `replace-in-file`, `switch-jdk`, `set-jvm-option`, `insert-plugin-version`, `show-dependency`, `pin-version` (Modul A; `file`, `artifact`, `version`), `remove-exclusion` (A4; `file`, `artifact`, `exclusion`, `section`), `add-exclusion` (A3; `file`, `artifact` = direkte Dep unter `dependencies`, `exclusion`), `add-dependency` (A5; `file`, `artifact`, `version`/`scope`/`type`/`classifier` nur wenn nötig), `remove-dependency` (A5; `file`, `artifact`, `classifier`), `set-scope` (A5; `file`, `artifact`, `scope`, `classifier`), `set-version` (A6; `file`, `version` + `property` (fehlt → anlegen) oder `artifact` + `section` = `parent`/`dependencies`/`dependencyManagement`), `manual`. POM-Typen laufen zentral über `PomEditor.forFix`/`isPomFix` (Kern: `FixExecutor`, Plugin: `FixRunner.editPoms` = ein Undo-Schritt + Reimport). `core/fix/FixExecutor` führt nur dateibasierte aus (`delete-files`, `replace-in-file`, `set-jvm-option` + POM-Typen); der Rest läuft im Plugin (`FixRunner`). Neuer Typ ⇒ FixAction-Konstante + Javadoc + Katalog-Kopfkommentar + `RuleCatalog.FIX_TYPES` + Ausführung (POM-Typ: `PomEditor.forFix`/`isPomFix` + `FixRunner.isSupported`/`run`).

## Schnappschüsse („Was hat sich geändert?“)

Ablage `~/.maven-detective/snapshots/<projekt>-<hash>/` (`green-*.json`, `latest-*.json`); verlegbar mit `-DmavenDetective.home` / `MAVEN_DETECTIVE_HOME`, aus mit `-DmavenDetective.snapshots=false`. Grüner Lauf = neue Referenz; kurze grüne Läufe (`validate`, `-pl`) dürfen die Referenz nicht ausdünnen. Zwischen IDE- und Extension-Schnappschuss nur vergleichen, was beide gleich messen. Fixture `09-changed-since-green` testet grün → Version ändern → rot.

## Preflight (`core/preflight/`) und Log-Navigator (`core/io/LogOutline`)

- `Preflight.run(projectDir, BuildSetup, Options)` → `Report` (`Item` je Befund: `Topic` SETTINGS/JDK/MAVEN/PROJECT/LOCAL_REPOSITORY/REPOSITORY, `Status` OK/INFO/WARNING/ERROR, `Evidence`, `FixAction`s wie auf der Karte; `getLight()` GREEN/YELLOW/RED, `getLocalRepository()`). Jede Prüfung liefert ≥1 Zeile. `PreflightContext` liest settings.xml (Benutzer aus `setup.getUserSettings()` sonst `~/.m2`, global aus `BuildSetup.getMavenHome()/conf`; SAX-Zeile aus der Cause), POMs über `ProjectPoms` + `PomLocator` (`missingPoms()` baut erst alle Modelle).
- `PreflightChecks`: Release = max über Module aus `maven.compiler.release/target/source` (interpoliert, Fundstelle = Property mit wörtlichem Wert) und `<release>`; mit `maven-toolchains-plugin` nur INFO + toolchains.xml-Prüfung; Enforcer-Bereiche über `VersionRange` (wie Enforcer, Unlesbares = erfüllt). Dependency ohne Version nur melden, wenn Kette und BOM-Importe vollständig sind. `maven-default-http-blocker` nie als eigener http-Mirror melden.
- **Netz nur mit `Options.network(true)`** (`RemoteRepositories` + `RepositoryProbe.HTTP`: HEAD, Proxy aus settings.xml inkl. `nonProxyHosts`, **nie Zugangsdaten**). Tests injizieren `Options.probe(...)`. Fehlende Parent/BOM nur dann „in keinem Repository“, wenn alle Repositories geantwortet haben (401/Fehler → kein Urteil).
- `BuildSetup.getMavenHome()`: Kommandozeile = MAVEN_HOME/PATH bzw. entpackte Wrapper-Distribution (`~/.m2/wrapper/dists/…`); IDE setzt `IdeMaven.mavenHome`. `MavenSettings.getProxies()/activeProxy(protocol)`.
- `LogOutline.of(lines)`: Zeilen 0-basiert; Module (`---< g:a >---` + `Building …`), Plugin-Schritte (`--- mojo (exec) @ x ---`), Reactor Summary (Ergebnis/Zeit), `BUILD SUCCESS/FAILURE`, `getFirstError()` überspringt `NOT_A_CAUSE` (`COMPILATION ERROR :`, `Tests run:` …), Download-Läufe ≥ `MIN_FOLD` als `Fold`. `isDownloadNoise(line)` ist auch die Grundlage der Konsolen-Faltung (schneller Ausstieg, verträgt ANSI/`\r`/`\n`).
- Plugin: `BuildDoctorPanel` hat Ansichten card/setup/preflight/log (`showView`). `PreflightView` (Host: back/check/runFix) – Fixes laufen über `FixRunner.run` mit synthetischem `Result` (Session-Repo = Preflight-Repo, Param `args` entfernt → kein Neubau). `BuildDoctorService.preflight(network, cancel)` (IDE-Setup, nicht auf EDT) + `preflightDone` → `Listener.preflightChanged` (Kachel in `OverviewPanel`). `LogNavigatorView` (Disposable, Editor per `EditorFactory.createViewer`, `clean()` entfernt ANSI/`\r` – Dokumente kennen nur `\n`). `DownloadConsoleFolding` (`console.folding`, Einstellung `foldDownloads`). Aktionen `MavenDetective.Preflight` (auch `Maven.NavigatorActionsToolbar`) und `MavenDetective.ShowLog`.
- Bundle: in `choice` kein `{n,number,#}` verschachteln (zweiten String-Parameter übergeben); Schlüssel nie zusammensetzen (`MavenDetectiveBundleTest` sucht Literale) – `switch` auf Enum.

Extension-Properties: `-Dmaven.ext.class.path=<jar>`, `-DmavenDetective.eventsFile=…`, `-DmavenDetective.report=false`.

## Modul A (`core/deps/`, Tab „Dependencies“)

- `PomFile`: rohe POM per SAX **mit Zeilennummern** (Properties, Dependencies, dependencyManagement, Parent); Profile nicht ausgewertet, nur gemeldet.
- `PomLocator`: Parent über `relativePath` → Reactor → lokales Repo; nie Netz; fehlende POMs in `getMissing()`.
- `EffectiveModel`: Mavens Reihenfolge nachbauen – erben (Kind gewinnt), im Kontext des **Kindes** interpolieren, dann BOM-Importe (erster gewinnt, BOM interpoliert im **eigenen** Kontext). Jede Angabe behält Datei+Zeile.
- `VersionExplainer` → `VersionExplanation` (Stationen mit `Kind`, Datei, Zeile, Level; `Source` DIRECT/MANAGED/BOM/TRANSITIVE/UNKNOWN). Baum optional (`DepNode`, aus IDE `IdeMaven.dependencyTree` oder `DependencyTreeParser` für `dependency:tree -Dverbose`).
- Tests bauen Projekt + lokales Repo in `@TempDir` (`VersionExplainerTest`). Plugin: `DependenciesPanel`, `WhyThisVersionAction` (EditorPopupMenu, nur `pom.xml`).
- **A2** `ConflictMatrix.build(locator, root, poms, trees)`: Zelle je Modul aus Baum (INCLUDED, BFS), ohne Baum nur direkte Deps (`isPartial`). Abweichende Zeile → `Pin` im **nächsten gemeinsamen Parent innerhalb des Projekts**, Version = `MavenVersion.max`; `Blocker` = direkte `<version>` oder Management näher am Modul (BOM-Importe blockieren nie). Spalten ohne Zellen bei `packaging pom` fallen weg.
- `PomEditor.pinManagedVersion` → `Edit` (offset/length/text/line): eigener Tag-Scanner, nur Pfade direkt unter `project` (Profile unberührt), behält Einrückung/Zeilenenden; vorhandener Eintrag → Version bzw. `${prop}` derselben POM ändern. Kein DOM-Roundtrip. Plugin wendet `Edit` aufs `Document` an (Undo), `FixExecutor` auf die Datei.
- Plugin: Tab `ConflictMatrixPanel` („Konflikt-Matrix“), Doppelklick → `DependenciesPanel.show`; nach Pin `IdeMaven.reimport`. CLI: `matrix [--tree …] [--all] [--markdown] [--pin g:a[:version]]`.
- **A4** `ExclusionAudit.build/audit`: je `<exclusion>` (nur in der POM notierte, `dependencies` + `dependencyManagement`) transitiven Baum der Dependency aus lokalen POMs nachbauen (`Closure`: compile/runtime, ohne optional, tiefere Exclusions gelten, erster Fund je GA gewinnt, Management des **prüfenden** Moduls vor Angabe der Dependency-POM) – einmal ohne Exclusions, einmal mit den übrigen. Status `USED`/`REDUNDANT`/`STALE`/`UNKNOWN`; fehlt eine POM → `UNKNOWN`, nie `STALE`. `PomFile.Dep` hat `getExclusionEntries()` (mit Zeile, `matches` mit `*`) und `isOptional()`.
- `PomEditor.removeExclusion(xml, g, a, "eg:ea", managed)`: Scan kennt jetzt alle Deps (`DepEntry` inkl. Exclusions); letzte Exclusion nimmt `<exclusions>` mit, ganze Zeilen weg; bei Duplikaten die erste.
- Plugin: `StaleExclusionInspection` (localInspection XML, `<depends>com.intellij.modules.xml</depends>`, Beschreibung `inspectionDescriptions/MavenDetectiveStaleExclusion.html`) liest die gespeicherte Datei, bildet Befunde über Struktur (nicht Zeilen) aufs PSI ab, Quick-Fix löscht PSI-Tag. Statischer `PomCache` (mtime+Größe) über `PomLocator(root, repo, cache)`.

- **A3** `ModuleClasspath.of(locator, pom, tree, reactor)`: mit Baum INCLUDED-Knoten in Preorder (= Maven-3-Classpath), `directDependenciesBringing(ga)` zählt auch CONFLICT/DUPLICATE-Pfade; ohne Baum je direkter Dep `ExclusionAudit.Closure` (hat jetzt `decls`), nearest wins, Gleichstand → erste Deklaration, Reihenfolge geschätzt. Managed Scope/Exclusions werden eingemischt. `target/classes` des Moduls (`isSelf`) und von Reactor-Modulen. JAR-Pfad nach Repo-Layout (`test-jar`→`-tests`, `ejb-client`→`-client`, Timestamp-Snapshots → `-SNAPSHOT`-Ordner).
- `JarIndex` (thread-sicher, Cache mtime+Größe; Plugin hält eine statische Instanz): Klassenname + CRC32 aus dem Zentralverzeichnis; ohne innere Klassen, `module-info`, `package-info`, `META-INF/`.
- `DuplicateClasses.build(locator, poms, trees, index, cancellation)` → `ModuleResult` (Clashes, `unreadable`) → `Clash` je JAR-Gruppe (`differing`, `isMain` = ≥2 nicht-Test-JARs). Empfehlung: Tabelle `KNOWN` (drop/keep-GAs) vor „komplett enthalten“ (bei mehreren: transitiv vor direkt, sonst der heutige Verlierer); sonst `drop == null`. `fixesFor(entry)`: `add-exclusion` je direkter Dep (im POM, wo sie deklariert ist), direkt deklariert → `open-file`.
- `PomEditor.addExclusion(xml, g, a, "eg:ea")`: nur `project/dependencies`, bevorzugt ohne Classifier, Duplikat → `IllegalArgumentException`. Plugin: Tab `DuplicateClassesPanel` (prüft erst auf Klick), `FixRunner.addExclusions` = ein Undo-Schritt + Reimport.
- **A5** Grundlage = Klassen, die die Quellen **beim Namen nennen** (`ClassUsages`: main/test, erste Fundstelle, Wildcards mit einfachen Namen der Datei). CLI: `SourceScanner` (Text ohne Kommentare/Strings, `src/{main,test}/{java,kotlin,groovy}` + `target/generated(-test)-sources`). IDE: `IdeUsages.collect` (PSI-Visitor löst Referenzen auf, je Datei `ReadAction.nonBlocking().inSmartMode().executeSynchronously()` + `ClassUsages.addAll`, Kotlin/Groovy über Scanner); Plugin hängt an `com.intellij.java`.
- `DependencyUsage.build(locator, poms, trees, index, UsageSource, cancel)`: Name → Eintrag (innere Klassen/Member abschneiden; main: erster compile/provided/system, sonst runtime; test: erster). `UNDECLARED` (nicht direkt, nicht deklariert; `isViaBundle` = über Starter ohne Klassen → CLI nur mit `--all`, IDE per Option), `UNUSED` (kein Name; Starter genutzt, wenn Mitgebrachtes genannt; runtime + Tabelle `RUNTIME_ONLY` nie; `JarIndex.Contents.getServices()` ⇒ `isCertain=false`), `TEST_ONLY` (compile/provided, nur Tests). Geerbte Deklaration → nur `open-file`. Reactor-Module ohne `target/classes` aus Quelldateinamen. Ohne Quellen kein UNUSED.
- **A6** `DependencyResolver.resolve(locator, pom)` → `Tree` (DepNode-Baum wie `dependency:tree -Dverbose`, `getMissing()`): BFS, nearest wins/erste Deklaration, Management des Moduls für Version/Scope/Exclusions transitiver Deps (`premanaged*` gesetzt), test/provided/system/optional nicht transitiv, Scope wie `JavaScopeDeriver`, Gewinner nimmt weitesten Scope (`JavaScopeSelector`). Verlierer CONFLICT/DUPLICATE/CYCLE, nicht expandiert.
- `UpgradeSimulator.simulate(locator, poms, Request, realTrees, cancel)`: `Planner` sucht den Hebel – Parent (`Target.PARENT`) → BOM-Import im Modell (`BOM`) → Artifact: direkte `<version>` / Management im Projekt / `${p}` (im Projekt definiert → dort, außerhalb → in oberster Projekt-POM überschreiben) / BOM mit gleicher Versionsnummer → BOM heben / sonst `pin-version` in `topmost` (oberste Projekt-POM der Kette); `Request.pinned()` (`--manage`) erzwingt Pin; `Request.property` (`name=wert`). Steps = FixActions (`set-version`/`pin-version`, Param `current`), im Speicher per `PomEditor.forFix` angewendet → `PomLocator.withOverrides(Map<Path,String>)` (parst via `PomFile.parse(path, xml)`, eigener Cache). Beide Bäume mit `DependencyResolver` (nie echten Baum mit Simulation mischen). `ModuleResult`: `Delta` (ADDED/REMOVED/UPGRADED/DOWNGRADED/SCOPE über INCLUDED-Knoten je g:a:type:classifier), neue `Risk` (CONFLICT-Verlierer verlangt höher), `note` (Ziel bleibt alt, Text aus `VersionExplainer`), `deviation` (simuliert-vorher vs. echter Baum). `missing` = nur neu fehlende.
- `PomFetcher`: einziger Netzzugriff in Modul A, nur auf Wunsch. Temp-POM mit fehlenden GAVs als `type=pom` + `<repositories>` der Projekt-POMs, `maven-dependency-plugin:3.8.1:collect` (nur POMs), `-Dmaven.repo.local`; `executable()` = `./mvnw` > `<mavenHome>/bin/mvn` > `mvn`. Bis 4 Runden, Schluss bei keinem Fortschritt. `UpgradeSimulator.localVersions(repo, g, a)` für Vorschläge.
- `PomEditor.setVersion(xml, section, g, a, v)` (parent/dependencies/dependencyManagement, ohne Classifier bevorzugt) und `setProperty(xml, name, v)` (fehlt → in `<properties>` bzw. neues `<properties>` vor dependencyManagement/dependencies/build). Scan kennt `parentFields/parentRanges`, `propertiesRange`, `dmStart`.
- Plugin A6: Tab `UpgradeSimulatorPanel` („Upgrade-Simulator“; Vorschläge aus Bäumen/Parents/BOM-Importen, Versionen lokal; „Fehlende POMs laden“ = `Task.Backgroundable` mit `JAVA_HOME` der IDE und `IdeMaven.mavenHome`; „Übernehmen“ = `FixRunner.editPoms`), `SimulateUpgradeAction` (EditorPopupMenu, `<dependency>` oder `<parent>`).
- `DependencyUsage.undeclared(cp, entry, class, test, file, line, index)` für die Live-Inspection `UndeclaredDependencyInspection` (Java-Imports; Classpath gecacht an `ProjectRootManager` + POM; `ModuleClasspath.find(Path | g, a)`).
