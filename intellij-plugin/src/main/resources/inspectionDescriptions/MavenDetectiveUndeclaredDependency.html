Reports imports of classes whose JAR the module does not declare itself but only gets transitively (Maven Detective, module A5).

If the dependency that brings it goes away or changes its own dependencies, the build breaks – without any change to your own pom.xml. Declaring what you reference by name keeps the classpath stable.

It is based on the classpath from the IDE’s Maven model (state of the last import). Classes from starters without classes of their own (such as spring-boot-starter-web) are not reported by default – declaring them is usually not needed there; the option below turns them on. Project-wide, including unused dependencies: the Usage page in the Maven Detective tool window or maven-detective-core.jar analyze.

Quick fix: declare the dependency in the module’s pom.xml (without a version if it is managed; with scope test if the import is in a test source).
