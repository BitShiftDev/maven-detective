Reports <exclusion> entries in the pom.xml that no longer exclude anything – typically after an upgrade of the dependency (Maven Detective, module A4).

Maven Detective rebuilds the transitive tree of the dependency from the POMs in the local repository, without the exclusion being checked. If the excluded artifact does not show up in it, the exclusion is stale. If it only comes through a path that another exclusion of the same dependency already cuts, it is redundant.

If POMs along the way are missing from the local repository, the inspection reports nothing – better no report than a wrong one. The same applies when a POM on the way is relocated or brings dependencies in a profile: Maven Detective does not rebuild those, so the exclusion is left alone. Build once, then it checks completely. Project-wide: Code | Inspect Code, the Exclusions page in the Maven Detective tool window, or maven-detective-core.jar exclusions.

Quick fix: remove the exclusion (for the last one together with <exclusions>). Like every POM change by Maven Detective it shows a diff preview first (unless switched off) and reimports the Maven project.
